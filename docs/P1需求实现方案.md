## 三、第二阶段详细功能设计

### 3.1 文件管理器（P0）

#### 3.1.1 功能需求

```
文件管理器应该支持：
✅ 树形展示项目文件结构
✅ 文件类型图标（HTML/CSS/JS/JSON等）
✅ 点击文件切换到编辑器
✅ 右键菜单：新建/删除/重命名
✅ 文件搜索
✅ 拖拽排序（可选）
```

#### 3.1.2 UI 设计

```tsx
// 文件管理器组件结构
<FileTree>
  <FileTreeItem name="index.html" type="html" />
  <FileTreeItem name="styles">
    <FileTreeItem name="main.css" type="css" />
    <FileTreeItem name="theme.css" type="css" />
  </FileTreeItem>
  <FileTreeItem name="app.js" type="javascript" />
</FileTree>
```

#### 3.1.3 技术实现

- 复用现有 `useProjectStore` 的 `files` 状态
- 添加 `createFile`、`deleteFile`、`renameFile` Actions
- 文件树组件使用递归渲染
- 通过 WebSocket 同步文件变更到后端

**决策原因**：
- 文件管理是代码编辑器的基础功能，没有文件树的编辑器体验很差
- 这是竞品的基本功能，必须具备
- 技术实现成本低，收益高

### 3.3 错误处理优化（P0）

#### 3.3.1 错误分类

```typescript
// 错误类型定义

  | 'llm_error'      // AI 服务错误

#### 3.3.2 错误展示

✅ 重试按钮
✅ 复制错误信息

#### 3.3.3 代码错误高亮

```
代码错误处理：
✅ 终端显示语法错误

✅ 错误行高亮标记

## 六、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| Inspect 模式实现复杂 | 中 | 使用 iframe 的 postMessage 通信，技术验证后再投入 |
| 一键部署需要后端服务 | 高 | 先实现静态文件导出，后续扩展到完整部署 |

| API Key 安全存储 | 中 | 本地加密存储，提示用户不要泄露 |

## 七、决策总结

### 7.1 第二阶段 P0 核心决策

**为什么文件管理器是 P0？**
- 代码编辑器没有文件树体验很差
- 技术实现成本低，收益高
- 是所有后续功能的基础

**为什么一键部署是 P0？**
- 竞品 Bolt.new 的核心功能
- 用户生成的应用不能分享，价值大打折扣
- 是产品传播的关键路径

**为什么 Inspect 是 P0？**
- 核心差异化点，Bolt.new 的标志性功能
- 提升调试效率，用户粘性高
- 技术有挑战，但值得投入

**为什么移动端适配是 P1？**
- 核心用户在桌面端
- 技术实现成本高
- 可以作为差异化功能延后实现
