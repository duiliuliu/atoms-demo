## 详细设计

### 1. 产品定位与目标用户

#### 1.1 产品定位

Atoms.dev 定位为 **AI 原生的全栈开发平台**，核心差异化在于：

- 多 Agent 协作开发（非单一 AI 助手）
- 全流程覆盖（需求分析 → 架构设计 → 开发 → 部署）
- 内置后端服务（Atoms Cloud）
- 实时预览与一键发布

#### 1.2 目标用户画像

| 用户类型 | 描述 | 标签 |
|----------|------|------|
| 创业者/独立开发者 | 有产品想法但缺乏技术能力，需要快速验证 MVP | 核心用户 |
| 产品经理/设计师 | 需要快速原型制作和功能演示 | 高频用户 |
| 初级开发者 | 学习编程或需要 AI 辅助提升效率 | 成长用户 |
| 小型团队 | 资源有限，需要降低开发成本 | 潜力用户 |

### 4. 交互设计规范

#### 4.1 对话交互

- **消息气泡**：用户消息右对齐，AI 消息左对齐，不同 Agent 使用不同头像标识
- **实时流式输出**：AI 回复逐字显示，提供打字机效果
- **代码块**：内嵌代码块支持语法高亮和一键复制
- **进度指示**：显示当前 Agent 工作状态和进度
- **计划确认**：开发计划以结构化卡片展示，支持选择性确认

#### 4.2 App Viewer 交互

- **Inspect 模式**：鼠标悬停高亮元素，点击选中
- **元素替换**：选中后弹出输入框描述替换内容
- **图片操作**：选中后出现"add or exchange"操作按钮
- **实时刷新**：代码变更后自动热更新预览
- **设备模拟**：支持桌面/平板/手机视口切换

#### 4.3 版本管理交互

- **Remix 分支**：一键从当前版本创建分支
- **版本列表**：右上角 Versions 按钮展开版本树
- **版本摘要**：每个版本自动生成变更摘要
- **快速切换**：点击版本即可切换查看

### 5. 视觉设计规范

#### 5.1 色彩体系

| 用途 | 色值 | 说明 |
|------|------|------|
| 主背景 | #0a0a0a | 深色主题基调 |
| 次级背景 | #1a1a2e | 卡片、侧边栏背景 |
| 主色调 | #6c63ff | 按钮、链接、强调 |
| 强调色 | #00d4aa | 成功、进度、完成状态 |
| 文字色 | #ffffff | 主要文字 |
| 次级文字 | #888888 | 辅助说明文字 |

#### 5.2 字体规范

| 用途 | 字体 | 字号 | 字重 |
|------|------|------|------|
| 页面标题 | Inter / SF Pro | 32-48px | 700 |
| 区块标题 | Inter / SF Pro | 20-24px | 600 |
| 正文 | Inter / SF Pro | 14-16px | 400 |
| 代码 | JetBrains Mono / Fira Code | 13-14px | 400 |
| 辅助文字 | Inter / SF Pro | 12-13px | 400 |

#### 5.3 设计风格

- **整体风格**：深色主题为主，科技感强，现代简约
- **圆角**：组件统一使用 8-12px 圆角
- **阴影**：使用柔和阴影增加层次感
- **动效**：微动画提升交互反馈（hover、transition、loading）
- **图标**：线性图标风格，统一 stroke width
- **间距**：基于 4px 网格系统

### 8. 决策考虑

#### 8.1 为什么选择深色主题？

- **专业感**：深色主题在开发者工具中更受欢迎
- **续航**：对 OLED 屏幕更省电
- **对比度**：代码和UI元素更易辨认
- **趋势**：主流开发工具（VS Code、GitHub）均支持深色模式

#### 8.2 为什么选择双栏布局？

- **效率优先**：同时查看对话和预览是最常见的使用场景
- **空间利用**：大屏幕用户需要更大的工作区域
- **渐进增强**：不同断点提供不同布局，平衡功能和空间

#### 8.3 为什么需要多Agent协作？

- **专业分工**：不同Agent负责不同领域，保证输出质量
- **SOP驱动**：标准化流程确保结果一致性
- **可扩展性**：新角色可随时添加
- **审核机制**：Agent之间可互相验证，减少错误

### 9. 实现方案

#### 9.1 技术选型

- **前端框架**：React 18 + TypeScript
- **样式方案**：Tailwind CSS + shadcn/ui
- **构建工具**：Vite
- **代码编辑器**：Monaco Editor
- **终端模拟**：xterm.js

#### 9.2 组件架构

```
components/
├── chat/           # 对话界面组件
│   ├── MessageBubble.tsx
│   ├── InputBox.tsx
│   ├── ModeSwitch.tsx
│   └── AgentAvatar.tsx
├── editor/         # 代码编辑器组件
│   ├── FileTree.tsx
│   ├── CodeEditor.tsx
│   └── TabBar.tsx
├── terminal/       # 终端组件
│   └── Terminal.tsx
├── preview/        # 预览组件
│   ├── AppViewer.tsx
│   ├── DeviceFrame.tsx
│   └── InspectOverlay.tsx
└── common/         # 通用组件
    ├── Button.tsx
    ├── Modal.tsx
    └── Tooltip.tsx
```

#### 9.3 状态管理

- **全局状态**：用户信息、项目配置、订阅状态
- **局部状态**：对话历史、编辑器内容、终端输出
- **实时同步**：WebSocket 保持多端状态一致
